# native/ agent notes

Native Android and iOS client (Expo SDK 58, React Native 0.88, TypeScript). Read
`ARCHITECTURE.md` first.

- No WebView for product UI. Native code goes in `modules/` (Kotlin, Swift) through the Expo
  modules API; `android/` and `ios/` here are generated by `expo prebuild` and not committed.
- `vendor/pockymoe/` is a pinned verbatim copy of runtime protocol code. Never edit it; run
  `npm run vendor:sync -- <runtime checkout>` and commit the new `SOURCE.json`.
  Browser-only modules are swapped at resolution (`resolver.cjs`), not patched.
- Layers: navigation presets → layout shell by width class → feature screens → design
  system → native. Feature screens never branch on width or platform.
- Follow the runtime repo's `docs/ui-principles.md`; reuse `src/design` primitives
  (`StatusMark`, `CopyButton`, `PathChip`, `MiddleName`, `ConfirmDialog`, `Sheet`, `Menu`).
- Use `npx expo install` for Expo and React Native packages. Checks: `npm run typecheck`,
  `npm test`, then an emulator build for UI changes (three themes × light/dark × phone/tablet).
- App id `com.pockymoe.app` (`APP_VARIANT=production`); development builds are
  `com.pockymoe.app.dev`, preview `com.pockymoe.app.preview`. Never `com.remotecodex.app`
  (the WebView shell) and never the shell's `pockymoe://` scheme.
