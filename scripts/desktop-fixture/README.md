# Desktop backend fixture

Run `./scripts/e2e-desktop-backend.sh start` from any directory. It starts a real
local Rust relay and three real relay-supervisors using FakeRuntime. Nothing is
mocked in the relay HTTP or WS transport. Python 3, curl, the existing Rust debug
binary and `apps/supervisor-web/dist/index.html` are prerequisites. The fixture
never builds, releases, deploys or restarts an existing supervisor.

The default relay origin is `http://127.0.0.1:18890`. All endpoints bind to loopback.
The account name is `desktop`. Disposable test credentials, device IDs, workspace
IDs, thread IDs and named scenario threads are written to the mode-0600 file
`.local/e2e-desktop-env.json`. `env` prints that file for test consumers; do not
include its contents in reports. Private provisioning tokens stay in the separate
mode-0600 state file and are never printed by status/start/verification.

```sh
./scripts/e2e-desktop-backend.sh start       # idempotent, preserves offline device
./scripts/e2e-desktop-backend.sh status
./scripts/e2e-desktop-backend.sh stop-device 3
./scripts/e2e-desktop-backend.sh start-device 3
./scripts/e2e-desktop-backend.sh start-turn 1 THREAD_ID
./scripts/e2e-desktop-backend.sh request-approval 1 THREAD_ID
./scripts/e2e-desktop-backend.sh request-input 1 THREAD_ID
./scripts/e2e-desktop-backend.sh complete 1 THREAD_ID
./scripts/e2e-desktop-backend.sh fail 1 THREAD_ID
./scripts/e2e-desktop-backend.sh burst 18
./scripts/e2e-desktop-backend.sh verify
./scripts/e2e-desktop-backend.sh stop        # retains the run's logs and data
./scripts/e2e-desktop-backend.sh serve       # foreground, stops on Ctrl-C/SIGTERM
```

Override `DESKTOP_E2E_RELAY_PORT`, `DESKTOP_E2E_SUPERVISOR_PORT` (first of three
consecutive ports), `DESKTOP_E2E_CODEX_ROOT`, `DESKTOP_E2E_BIN` and/or
`DESKTOP_E2E_WEB_DIST` before start. Occupied ports fail rather than reusing an
unverified service. Port 45679 is explicitly forbidden. A missing debug binary is
retried briefly to accommodate another engineer linking it; no substitute is built.

## Seed and transport

Each device has 81 threads in six workspaces: 60 root threads, plus 1–6 delegates
under one root per workspace, including depth-three lineage and closed delegates.
There are mixed Chinese/English titles (including very long titles), Codex/Claude/
ACP providers, favorite workspaces, pinned threads, completed historical turns with
user/assistant messages and token usage, failed turns, and recent unread candidates.
Each device starts with one held running turn, one pending approval, one pending
input question and one recent failed turn. The last two workspaces on each device
are entirely older than 14 days and unpinned; the other workspaces include threads
on both sides of the 7-day/14-day boundaries. IDs are generated by the runtime;
scenario layout, titles, age offsets and token amounts are deterministic.

Accounts, devices, workspaces, favorites, threads and lineage are created through
the public HTTP API, traversing the relay. There is no public timestamp/pinning/
agent-metadata import API. After HTTP creation, only the fixture's three recorded
supervisors are stopped. `seed.py` then uses transactions on those new SQLite
files to backdate timestamps over 60 days and insert completed history, pin flags,
delegate names and closed timestamps. It uses existing schema, never migrates it,
and asserts that the database lives in this run's directory. Supervisors restart
before live events are seeded through the API. No live SQLite writes are used.

Live controls require the fake-only runtime endpoint `POST /api/e2e/events` with
`{type: "start"|"complete"|"fail"|"approval"|"input", threadId}`. Controls operate
on real turns/requests and publish the ordinary thread bus events. A binary without
this endpoint causes an explicit startup error; partial fixtures are stopped.
`complete` and `fail` may also start and immediately finish a fresh turn. `burst N`
uses up to 66 distinct non-scenario threads and checks that all requests finish in
under a second. Starting a stopped device restores its active scenario turns and
requests; the normal supervisor recovery semantics apply to other interrupted turns.

`verify` logs in with curl, checks the relay serves HTML, lists every device's
threads/workspaces, opens each device's relay `/ws`, and checks started, completed,
failed, request-created and request-resolved events plus persisted pending requests.
It then checks 18 completion events across all three device streams within one
second. Evidence is written without credentials to
`/tmp/rc-desktop/evidence/fixture/verification.json`.

```sh
bash -n scripts/e2e-desktop-backend.sh
python3 -m py_compile scripts/desktop-fixture/*.py
python3 -m unittest discover -s scripts/desktop-fixture -p 'test_*.py'
python3 scripts/desktop-fixture/verify_lifecycle.py
```
