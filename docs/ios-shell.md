# iOS thin shell

The app generated by `ios/project.yml` compiles `ios/Shell` and `ios/Shared`.
Retired native product screens remain outside the target until the required
browser/touch E2E passes. Bundle identity stays `com.remotecodex.app`; display
name is Pockymoe. Product UI lives in one full-screen WKWebView.

## Connection

There is no default address. The first connection form has a service field with
`https://app.example.com` as its placeholder, and Advanced for a separate Relay.
The shell probes the entered origin with an ephemeral URLSession: no cookies,
credential store or authorization, at most four validated redirects, a 2 MiB
response limit, bounded timeouts and normal TLS certificate verification.
Release accepts HTTPS only; Debug also accepts loopback HTTP.

A response must be successful Pockymoe HTML (the named product, SPA root and
script). If an API-only Relay redirects to another origin serving that HTML, the
final origin is Web and the entered origin is Relay. Direct Web gives the same
origin for both. Advanced overrides Relay. Failure stays on the form with one
inline explanation and preserves the typed address; it never opens offline UI.
The resolved Web host must also be allowed by this build's configuration below.

A previously stored Web/Relay pair is kept. A legacy `relay_url` without a saved
Relay goes through this same probe once, silently. Success stores the resolved
pair; failure leaves a filled connection form and an explanation. The attempt
and failure are remembered so a failed upgrade is not probed again every launch.
No legacy endpoint is replaced with a default address.

An already-connected page that cannot load shows the native offline page with
primary **重试** and secondary **更改地址**. Change returns to the form with the
current service/Relay filled and clears the old activity metadata. Retry reloads
the current route. Background/foreground keeps the same WebView and route.

## Why the app-bound list is still needed

The HPKE/AEAD exchange itself runs in the page, not in a Service Worker. The Web
already has page-level encrypted fetch, WebSocket and blob-download paths.
However, the current Web forces `ensureRelayWorker()` before encrypted API and
WebSocket setup, and a worker also handles direct protected-resource URLs used
by the DOM (thread image assets, workspace raw resources and embedded content).

Removing the worker requirement from API/socket setup alone would leave direct
resource loads without decryption. A complete no-worker Web needs alternate
asynchronous resource/blob loading, URL lifetime and embedded-resource handling,
plus media/preview/download regression coverage. That is a separate Web change,
not a safe native flag change. The current client therefore uses app-bound mode
with an explicit private build allowlist. No production address is committed.

Create the ignored file `ios/Local.xcconfig` locally:

```xcconfig
POCKYMOE_APP_BOUND_HOSTS = web.your-domain.test
```

Use actual hostnames without protocols, ports, paths or wildcards, separated by
commas. The Release pre-build script **fails** if this file/setting is missing,
empty, invalid or contains the example placeholder. At most ten hosts are allowed.
The script generates the build's Info.plist in DERIVED_FILE_DIR; tracked templates
contain no host list. Debug additionally permits loopback hosts for isolated E2E.
`Config/Build.xcconfig` optionally includes this local file, which git ignores.

**These hosts are readable in the distributed binary's Info.plist.** Keeping the
xcconfig out of Git does not make packaged hosts secret. A build author must
accept that disclosure and supply the Web hosts the installation will use.
An arbitrary host cannot be added to the signed app-bound list at runtime.
A missing host is explained on the connection form instead of trapping someone
on an unusable WebView. The Relay may be a separate origin and does not receive
an injected bridge.

## Bridge and authentication

`web/pockymoe-host.js` is injected at document start only into the configured
Web origin's top frame. Native handlers independently verify the current origin
and message frame; replies are tied to a document generation. The shared legacy
`web/native-bridge.js` remains unchanged for Android.

`settings.get()` reports the resolved Web/Relay pair. System-browser sign-in
accepts the configured Relay's Google/GitHub start paths as well as the service's
start paths and the recognized provider pages. Invalid origins or failure to
start are rejected with a useful error; only explicit cancellation returns null.
ASWebAuthenticationSession keeps the existing `remotecodex` callback scheme.
The page/Relay owns the proof-bound OAuth handoff; native session data never enters
the page. Provider credentials and a real provider round trip are separate from
local sign-in acceptance.

The page owns routes, menus and back ordering. Mobile Preferences and pet methods
are no-ops. Native exports are limited to 32 MiB. Safe-area geometry reaches CSS
`env(safe-area-inset-*)`; the shell adds viewport-fit=cover. Appearance uses the
page's supplied background, including WebKit-to-sRGB conversion of CSS Color 4
values, so the next launch does not paint an unrelated root-variable color.

## Sign-out and legacy sessions

The page's `pockymoe-account-logout` event immediately sends a private bridge
message that clears cached activity titles/device/workspace metadata and batch
policy, cancels old token observation, invalidates queued old snapshots and suppresses late page snapshots until the
next browser-registration event, then ends
system activities. A later sync from another account is not required. The same
cleanup occurs when changing the service address.

At upgrade the old `relay_token` is removed from UserDefaults immediately. A
best-effort POST to the **previously stored Relay's** `/relay/auth/logout` revokes
it. This ephemeral request never follows redirects and never installs a native
session into the WebView. Failure does not put the old plaintext token back into
storage. Current APNs registration belongs to the page and authenticated Relay
session; foreground native notifications are suppressed and taps route to the
same WebView.

## ActivityKit wire format

One local activity summarizes an account, grouping agent rows under their root
conversation. A foreground running thread starts it, waiting prevents ending,
and all-terminal work keeps the completed summary for 15 minutes. Titles and
location metadata stay in an account-scoped local App Group cache.

`PockymoeActivityAttributes` contains `accountId`; content-state is
`ActivityContentState`: at most three rows (`key`, `state`, `startedAt`),
`totalCount`, `waitingCount`, `failedCount`, `runningCount`, `completedCount`,
`earliestStart`, and nullable `endedAt`. Keys are `deviceId:threadId`; no title,
request/result text, device or workspace name is in an APNs content-state.
Unknown metadata uses “线程运行中” and derives routing from identifiers.

ActivityKit uses the default Codable Date strategy: **content-state dates are
seconds since 2001-01-01 UTC**. APNs envelope `timestamp` and `dismissal-date` are
**Unix seconds**. The exact Relay update/end golden JSON files are copied into
`ios/ActivityPolicyTests/Fixtures`; Swift tests decode those bytes with an
unmodified JSONDecoder and verify both epochs and the 900-second dismissal rule.
The Relay owns content-free push delivery; no push-to-start is used. Activity
push tokens go through the agreed `liveActivityToken` command.

## Checks and standalone acceptance

```sh
export DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer
xcodegen generate --spec ios/project.yml
xcodebuild build -project ios/RemoteCodex.xcodeproj -scheme RemoteCodex \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-
swift test --package-path ios
node --test tests/ios-host.test.mjs tests/native-bridge.test.mjs
```

A local ad-hoc signature is needed for the simulator's nonextractable CryptoKey
persistence. An unsigned app can compile/install while encrypted login fails
with DataCloneError. No Apple developer identity is required for this signature.
Run an isolated backend with explicit ports and data; never inherit production
Supervisor settings. `E2E_WEB_ORIGIN` lets `e2e-backend.sh` model an API-only Relay
redirecting to separate static Web. The Web build's Relay configuration must
match the chosen test Relay.

`--debug-harness` enables async JavaScript step batches in the app container's
`Documents/acceptance.json`. Scripts are function bodies with optional polling
(`wait:true`, `timeout`). The runner checks page readiness, writes progress/final
JSON, deletes consumed input and cancels on teardown. All code is under #if DEBUG.
Use `scripts/ios-debug-run.py` to write/wait without printing script contents.
Generated login inputs belong in ignored `.local`; never share fixture tokens.

`scripts/ios-review-setup.py` exercises first connection and the legacy probe;
`scripts/ios-review-server.py` supplies isolated static Web and redirect/failure
fixtures. `--debug-setup-fixture` reads Documents/setup-fixture.json and runs the
real native probe; `--debug-record-setup` observes a normal subsequent launch.
DEBUG file signals can invoke the actual Retry, Change address or auth cancel
actions and inspect metadata counts; they do not grant notification permission.

`scripts/ios-debug-steps.py` generates login/protection/thread/send batches.
`scripts/ios-record-launch.py` captures cold launch through scripted readiness;
`scripts/ios-video-frames.swift` samples the recording. Theme/island capture tools
remain available. `E2E_ACTIVITY_STATE` selects running/needsInput/failed/interrupted/
overflow/completed fixtures. `E2E_RENDER_ISLANDS=1` generates 48 ImageRenderer PNGs
using the Widget's shared views. Minimal review uses a DEBUG companion activity;
production remains one per account. Contact sheets label **renders** separately
from **real system captures**. Inspect the images; a successful Activity.request
alone is not system-presentation evidence.

Only use a dedicated simulator UUID. XCTest remains a separate acceptance layer:
scripted DOM actions cannot prove real edge-swipe tracking, keyboard behavior under
touches, notification taps, provider OAuth completion, hardware haptics or APNs.

## Signing prerequisites

An installable IPA needs matching app and Widget provisioning profiles. The main
app profile must allow Push Notifications (`aps-environment`) and registered
App Group `group.com.remotecodex.app`; the Widget profile needs the same group.
Local Live Activities use `NSSupportsLiveActivities`, not an additional standard
signing entitlement. Live Activity pushes also need correctly configured APNs
sender/topic credentials. A simulator ad-hoc signature is not device distribution
signing. No certificate, team or provisioning change is performed by local tests.
