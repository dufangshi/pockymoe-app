# Pockymoe 手机端设计

iOS 和 Android 与桌面端同一架构：系统壳 + 线上 Web UI + `window.pockymoeHost`。产品界面只有 Web 一份，线上更新后手机立刻同步。壳只做 Web 做不好的事。界面规则见 Pockymoe 仓库的 `docs/ui-principles.md`。

## 1. 壳里保留什么

- 没有默认地址。首次启动显示连接页，询问服务地址，输入框占位符为 `https://app.example.com`；高级选项可填写单独的 Relay 地址，与桌面客户端的连接页一致。已有安装继续使用已经保存的地址。全屏 WebView 加载填写的服务地址。
- 本地页只有两个：连接页（填服务地址，可选单独的 Relay 地址）和离线页（说明连不上，带重试）。它们是本地界面，因为此时页面还加载不出来。文案和外观跟随 Web。
- 其余原生页面（登录、设备、工作区、线程列表、设置等）全部删除，由 Web 接管。删除前，端到端测试要证明 Web 已覆盖这些流程。
- Bundle ID 和 applicationId 不变（`com.remotecodex.app`），否则现有安装无法升级。显示名改为 Pockymoe。

## 2. 第三方登录

Google 不允许在内嵌 WebView 里登录。Google 和 GitHub 登录要走系统认证页（iOS 用 `ASWebAuthenticationSession`，Android 用 Custom Tabs），完成后通过深链回到 App，在 WebView 里落下登录态。用户不能感觉到离开了 App 又回来时丢了状态。

## 3. 不闪、不跳

这是最重要的验收项。

- 启动：系统启动屏是纯色，没有 Logo，深色模式 `#17171A`，浅色模式 `#FAFAF8`。壳记住上次页面的背景色，用它铺底。页面首帧画好才显示 WebView，用 120ms 淡入。全程不能出现白屏。
- 系统栏：状态栏透明，内容铺满，页面用 `env(safe-area-inset-*)` 避让。状态栏图标深浅、Android 导航栏颜色都跟随 `appearance.sync` 实时切换。
- 键盘：键盘升起时输入框贴着键盘走，消息不跳。只调整可视视口，不让整页被顶起来。键盘上方不显示 iOS 的“上一项/下一项/完成”工具条。
- 回弹：根页面关闭橡皮筋回弹，顶部和底部不露出底色。可滚动区域内部保留系统惯性。
- 切到后台再回来：保留原来的页面和滚动位置，不重新加载。只有系统回收过 WebView 时才恢复路由。
- 长按：链接不弹系统预览；消息内容允许选字；导航和按钮不可选字。

## 4. 手势

- iOS 从左边缘右滑返回，跟手；Android 用预测性返回。
- 返回的顺序：先关最上层的菜单或底部面板，再回上一个路由，到根页面时才退到桌面。由 Web 决定，壳通过 `onCommand` 发 `back`，Web 回答是否已处理。
- 触感反馈只用在三处：发送成功（轻）、等待你的请求出现（提醒）、危险操作确认（警告）。滚动和普通点击没有触感。

## 5. 通知

- 标题和点击去向与桌面端相同。点击通知直接打开那个线程，从冷启动到线程页中间不经过别的页面。
- 通知正文保持 Relay 的通用文案。线程内容不离开 Supervisor，所以不能让 Relay 把线程内容放进推送。
- 同一事件在 App 在前台时不弹系统通知，由页面内提示。

## 6. 灵动岛与实时活动（iOS）

一个账号只有一个实时活动，汇总所有线程，不是一个线程一个。否则线程多的时候会刷屏。

| 位置 | 内容 |
| --- | --- |
| 紧凑·左 | 18pt 状态标识，视觉居中。优先级：等待你 > 失败 > 运行中 |
| 紧凑·右 | 等待你时写数量；运行中写最早那一轮的已用时间（`Text(timerInterval:)`，等宽数字） |
| 最小 | 只有 16pt 状态标识，视觉居中 |
| 展开 | 第一行：状态标识、线程标题（一行，中间省略），右侧已用时间。第二行：设备 · 工作区，次要文字色。第三行：等待你时写「等待你处理」；运行中没有其他线程时写「运行中」，有其他运行线程时写「还有 N 个线程在运行」；已中断写「已中断」；失败写「运行失败」，有其他运行线程时写「运行失败 · 还有 N 个线程在运行」。不显示「还有 0 个线程在运行」。没有操作按钮，点击打开该线程 |
| 锁屏 | 圆角卡片，最多三行，每行是状态标识、标题、设备、时间；超出时写「其余 N 个」。背景跟随系统深浅，不用强调色铺底 |

- 状态标识用 `ui-principles.md` §6 的形状，从 Web 的 SVG 转成矢量资源。琥珀色气泡表示等待你，红色菱形表示失败。
- 实时活动不能循环自绘动画。运行中用静止的圆环，靠不断走动的时间表示还在跑。这是 §6 的例外，要在该文档和代码注释里写明原因。
- 开始：有线程开始运行且 App 在前台时启动。
- 结束：所有线程都结束后显示「N 个线程已完成」，保留 15 分钟后消失。有等待你的请求时不结束。锁屏和展开态沿用普通行的结构，左侧完成圆点后接这句文字，整行左对齐，不把文字居中。
- 行内时间使用等宽数字和固定宽度的尾部栏位，计时位数变化时不能挤动标题。
- 第一版不在灵动岛里批准或拒绝。批准需要设备端的加密通道，放在系统组件里有安全风险。

**数据来源和隐私**：标题和设备名只来自页面的 `activity.sync`，保存在本机。App 被挂起后，Relay 通过 APNs 的 `liveactivity` 推送只能更新不含内容的字段：各状态的数量、线程 ID、时间。新线程没有标题时，写「线程运行中」。不用 push-to-start，因为那样必须让 Relay 下发内容。

## 7. Android 的对应方式

- Android 16 及以上用 Live Updates（`Notification.ProgressStyle`、`setShortCriticalText`），状态栏胶囊和通知内容对应第 6 节，同样一个账号一条。
- Android 8 到 15 用普通的持续通知，内容相同，但没有状态栏胶囊。
- 现有的前台服务继续负责 App 在后台时收事件，它不依赖 Google 服务，在 AOSP 和没有 GMS 的手机上也能工作。常驻通知就是上面这一条，不再另外多一条。
- FCM 需要 Firebase 项目和 Relay 发送端，现在都没有，这一版不做，把接入点留清楚。

## 8. 验收

iOS 模拟器（iPhone 17 Pro，灵动岛机型）和 Android AOSP 模拟器各走一遍：冷启动无白屏、登录、打开线程、发消息、键盘、返回手势、通知点击、切后台再回来、断网再恢复、深浅色切换、灵动岛或 Live Updates 各状态。Classic、Plum Pocket、Terminal 三个主题的浅色和深色各截图。Live Activity 的 Relay 推送在模拟器上用本地推送模拟，真机验证单独列出。
